# 变更提案: Emby 服务器配置与手机同步

## 需求背景
当前 TV 端设置页只提供 `Server Address`、`Username`、`Password` 三个输入项，服务器地址需要用户手动拼完整 URL。参考设计稿中的“添加服务器”弹窗，需要把服务器连接信息拆分为更适合电视输入的结构化字段，并支持通过手机扫码填写后同步回电视，降低遥控器输入成本。

## 产品分析

### 目标用户与场景
- **用户群体:** Android TV 上使用 Emby 的家庭用户，主要通过遥控器完成初始化配置。
- **使用场景:** 用户第一次打开 TV 客户端，需填写 Emby 服务器地址、协议、端口、路径、用户名和密码；也可能更愿意用手机键盘输入这些内容。
- **核心痛点:** 遥控器输入 URL、用户名和密码效率低；完整 URL 对普通用户不直观；协议和端口的常见默认值应自动处理；密码只应作为登录换取凭证的临时输入，不应长期保存；用户名需要保存为用户身份展示字段，方便后续多服务器/多用户区分。

### 价值主张与成功指标
- **价值主张:** TV 端字段更清晰，手机扫码输入更高效，配置同步后仍由 TV 端完成连接确认。
- **成功指标:** 用户可在 TV 端或手机浏览器填写同一组字段；协议切换能自动给出正确默认端口；手机点击“同步到电视”后 TV 表单实时更新。

### 人文关怀
密码输入和同步过程必须避免日志输出、错误提示暴露和长期保存。手机同步仅在同一局域网临时开放，并用一次性配对令牌限制误同步。

## 变更内容
1. 将当前单一 `serverUrl` 输入改为 6 个配置字段：服务器地址、协议、端口、路径、用户名、密码。
2. 协议支持 `https` 与 `http` 二选一；`https` 默认端口为 `443`，`http` 默认端口为 `8096`。
3. 增加服务器配置草稿模型，将结构化字段规范化为 Retrofit 可用的 `baseUrl`。
4. 将 Quick Setup 占位码替换为 TV 本机临时同步二维码。
5. 手机浏览器访问二维码页面后展示同一组配置字段，并提供“同步到电视”按钮。
6. TV 端接收手机同步内容后更新表单状态，不自动登录，仍由用户在 TV 端确认连接。
7. 对齐 Emby 官方认证交互：用户名和密码用于 `/Users/AuthenticateByName` 换取访问令牌；认证成功后保存 `AccessToken`、`UserId`、`ServerId`、`serverUrl`、`deviceId` 和 `username`，其中 `username` 仅用于展示和区分用户身份，不作为认证恢复凭证；密码不保存。

## 范围边界
- **范围内:** TV 设置页字段重构、默认端口规则、baseUrl 规范化、手机扫码同步页、本地同步接口、二维码展示、官方认证凭证策略、相关状态和测试。
- **范围外:** Emby 官方 pin 配对、云端中转服务、多服务器列表管理、多设备账号同步、自动发现 Emby 服务器、同步后自动登录、长期保存密码。
- **拆分说明:** 本方案只覆盖初始化配置输入和同屏同步闭环，不扩展媒体库、播放、弹幕或账号管理能力。

## 影响范围
- **模块:** ui、domain、data、core/network、build。
- **文件:** `SetupScreen.kt`、`HomeUiState.kt`、`HomeViewModel.kt`、`ServerConfig.kt`、`EmbySession.kt`、`EmbyApiFactory.kt`、新增凭证存储、手机同步服务与二维码工具、相关测试、知识库文档。
- **API:** 变更 ViewModel 更新方法和 `ServerConfig` 构造来源；新增 TV 本机临时 HTTP 接口。
- **数据:** 新增可持久化的 Emby 会话凭证；`username` 可作为展示字段落盘，密码和手机同步提交体只保存在内存态，不落盘。

## 核心场景

### 需求: TV 端结构化服务器配置
**模块:** ui, domain, data
用户在 TV 设置页填写服务器配置时，应看到与参考图一致的结构化字段。

#### 场景: 默认协议与端口
用户打开设置页：
- 默认协议为 `https`。
- 默认端口为 `443`。
- 用户切换到 `http` 且端口未被手动改写时，端口自动变为 `8096`。
- 用户切回 `https` 且端口仍为协议默认值时，端口自动变为 `443`。

#### 场景: 拼装 Emby baseUrl
用户填写服务器地址、协议、端口和可选路径后点击连接：
- `服务器地址` 只填写主机名或 IP，不要求输入协议。
- `路径` 为空时生成 `protocol://host:port/`。
- `路径` 为 `emby` 或 `/emby/` 时生成 `protocol://host:port/emby/`。
- 用户名必填，密码允许为空。
- 非法端口、空服务器地址或空用户名时显示可恢复错误。

### 需求: 手机扫码同步配置
**模块:** ui, core/network
用户可用手机浏览器填写同一组字段，并同步到电视端。

#### 场景: TV 展示扫码入口
用户停留在设置页：
- Quick Setup 区域展示真实二维码和短说明。
- 二维码内容指向 TV 本机局域网地址，例如 `http://<tv-ip>:<sync-port>/?pair=<token>`。
- 同步服务只在设置页可见期间启动，离开设置页或连接成功后停止。

#### 场景: 手机填写并同步
用户扫码打开手机页面：
- 手机页面展示服务器地址、协议、端口、路径、用户名、密码。
- 手机页面协议切换遵守同样默认端口规则。
- 用户点击“同步到电视”后，TV 设置页表单更新为手机填写的内容。
- 手机页面显示同步成功或失败提示，不展示密码明文回显。

### 需求: Emby 官方认证凭证策略
**模块:** data, domain
客户端应按 Emby 官方 API 使用用户名和密码换取访问令牌，再使用令牌访问后续接口。

#### 场景: 登录换取凭证
用户点击连接：
- TV 端向 `/Users/AuthenticateByName` 提交用户名和密码。
- 登录成功后读取响应中的 `AccessToken`、`User.Id` 和 `ServerId`。
- 后续媒体列表、图片、播放流请求使用访问令牌，不再使用用户名和密码。

#### 场景: 保存登录态
用户登录成功后：
- 本地保存 `serverUrl`、`userId`、`accessToken`、`serverId`、`deviceId`、`username` 和保存时间。
- 不保存密码；`username` 只作为非敏感展示字段保存，用于后续多服务器/多用户列表区分身份，不作为认证恢复依据。
- 访问令牌失效或被服务端注销时，清除本地凭证并提示重新登录。

## 风险评估
- **风险:** 手机与 TV 不在同一局域网时无法访问 TV 本机同步页。
- **缓解:** TV 页面显示同步 URL 和错误状态；保留 TV 端手动输入作为兜底。
- **风险:** 手机到 TV 的本地 HTTP 同步会在局域网内传输密码。
- **缓解:** 使用一次性高熵配对令牌、短生命周期、单次同步后失效、不记录请求体、不跨网段中转；提示用户仅在可信局域网使用。
- **风险:** `AccessToken` 是可直接访问 Emby 的 bearer 凭证。
- **缓解:** 使用 Android 私有加密存储保存 token；日志、错误文案和页面 URL 均不得包含 token 或密码。
- **风险:** 新增本地 HTTP 服务和二维码依赖带来兼容与安全审计成本。
- **缓解:** 依赖统一放入 `libs.versions.toml`，执行阶段运行单元测试、Debug 构建，并检查依赖版本与已知漏洞。
