# 变更提案: TV UI 设计稿核心体验落地

## 需求背景
当前 Android TV 客户端仍处于初始化状态，`HomeScreen` 同时承担服务器连接与媒体列表，`PlayerScreen` 依赖 Media3 默认控制器，视觉和交互尚未对齐提供的设计稿。用户提供的 `C:/Users/MyPC/Downloads/stitch_emby_tv_interface_redesign.zip` 包含 Cinematic Glass 设计系统和 5 个关键场景，需要先整理功能范围并形成可执行方案。

设计稿覆盖场景如下：
1. `cinematic_glass/DESIGN.md`: 深色 Cinematic Glass 设计系统、颜色、字体、间距、焦点与 OSD 规范。
2. `_4`: 服务器配置页，包含快速配对码、手动服务器地址/API Key 输入和连接按钮。
3. `_3`: 首页媒体中心，包含顶部栏、抽屉导航、媒体库入口、继续观看、迷你播放条。
4. `_2`: 媒体详情页，包含影片元数据、播放/预告片/收藏操作、演员列表、演员关联内容。
5. `_1`: 收藏与人物页，包含收藏筛选、人物英雄区、混合媒体/人物卡片和作品集。
6. `osd`: 播放 OSD，包含标题元信息、弹幕层、音轨/字幕/弹幕快捷设置、进度条、播放控制和状态 Toast。

## 产品分析

### 目标用户与场景
- **用户群体:** 使用 Android TV/盒子观看 Emby 媒体库的家庭影院用户，主要通过遥控器在 10-foot 距离操作。
- **使用场景:** 首次配置服务器、回到首页选择媒体库、继续观看、进入全屏播放并控制字幕/音轨/弹幕。
- **核心痛点:** 初始化界面信息密度低、视觉未体现媒体内容、播放控制与弹幕设置不够贴近 TV 场景。

### 价值主张与成功指标
- **价值主张:** 用统一的 Cinematic Glass 视觉系统把“配置-浏览-播放”主链路打通，让客户端具备可演示、可继续扩展的 TV 体验骨架。
- **成功指标:** 首页首屏能展示媒体库和继续观看入口；播放器 OSD 能用遥控器唤起、隐藏和控制播放；弹幕层能与播放暂停状态同步；核心路径通过单元测试和 Debug 构建验证。

### 人文关怀
大屏 UI 需要保证远距离可读、焦点明确、操作路径短。服务器地址、Token/API Key 等敏感信息不应在 UI、日志或知识库中明文持久化。

## 变更内容
1. 抽取 Cinematic Glass 主题 token 与可复用 TV 组件，统一颜色、字体层级、间距、安全区、玻璃面板、焦点态和媒体卡片表现。
2. 将当前 `HomeScreen` 拆分为服务器配置、首页媒体库和播放入口三个可维护 UI 区域。
3. 规划首页抽屉导航、媒体库卡片、继续观看行、空态/错误态和迷你播放条。
4. 替换默认播放器控制体验，规划 Compose OSD、弹幕快捷设置、音轨/字幕占位入口、遥控器按键处理和自动隐藏逻辑。
5. 补齐 ViewModel/UI 状态测试和手工截图验证清单，保证首批核心体验可执行。

## 范围边界
- **范围内:** 服务器配置页、首页媒体库页、播放页 OSD/弹幕控制、共享设计系统、现有 Emby 登录/媒体列表/播放能力的 UI 重组。
- **范围外:** 详情页完整实现、人物/收藏页完整实现、真实快速配对 API、真实字幕搜索、真实音轨/字幕切换、设置页、离线缓存、投屏、多用户管理。
- **拆分说明:** 设计稿覆盖面较大，本方案包选择风险最低且价值闭环最清晰的“配置-首页-播放”主链路。详情页与人物/收藏页依赖更完整的 Emby 元数据、路由和筛选能力，应作为后续独立方案包。

## 影响范围
- **模块:** `ui`、`player`、`danmaku`、`data`、`core`、知识库。
- **文件:** 预计新增/修改 `app/src/main/java/com/embytv/ui/theme/*`、`app/src/main/java/com/embytv/ui/components/*`、`app/src/main/java/com/embytv/ui/setup/*`、`app/src/main/java/com/embytv/ui/home/*`、`app/src/main/java/com/embytv/ui/player/*`、`app/src/test/java/com/embytv/ui/*`、`gradle/libs.versions.toml`、`app/build.gradle.kts`、`helloagents/main/wiki/modules/ui.md`。
- **API:** 保持 Emby 远端 API 不变；内部 UI 状态模型会新增页面模式、选中库、OSD 可见性、弹幕开关等字段。
- **数据:** 不做数据库或持久化迁移；服务器地址、用户名和密码仍维持当前运行期状态，敏感信息不得写入日志或知识库。

## 核心场景

### 需求: Cinematic Glass 设计系统
**模块:** ui
将设计稿中的颜色、间距、焦点态和玻璃面板抽取为 Compose 可复用主题/组件。

#### 场景: 遥控器焦点可见
用户使用方向键移动焦点时：
- 被聚焦的卡片、按钮、输入框显示 Emby Green 边框或强调态。
- 元素缩放不挤压邻近内容，不造成文字重叠。

#### 场景: 10-foot 可读
用户在 4K/1080p 横屏电视上查看页面时：
- 标题、正文、标签和媒体元信息使用清晰层级。
- 页面保留横向和纵向安全区，避免贴边。

### 需求: 服务器配置页
**模块:** ui
用设计稿 `_4` 替换当前左侧表单式连接体验，作为未登录/未连接状态的首屏。

#### 场景: 手动连接
用户输入服务器地址、用户名和密码后点击连接：
- 继续复用当前 `HomeViewModel.connect()` 认证流程。
- 加载中、错误、成功状态在配置页内有清晰反馈。

#### 场景: 快速配对占位
用户看到快速设置区域时：
- 显示配对码/二维码占位和说明。
- 标明该能力为 UI 占位，不调用真实 Emby Connect 配对接口。

### 需求: 首页媒体中心
**模块:** ui
用设计稿 `_3` 重组已连接状态的首页。

#### 场景: 媒体库浏览
用户认证成功并加载媒体后：
- 首页展示媒体库入口、继续观看横向媒体行和媒体卡片。
- 卡片使用 Emby 图片 URL；图片缺失时显示稳定占位。

#### 场景: 导航抽屉
用户点击菜单或遥控器触发菜单时：
- 抽屉显示 Home、Movies、TV Shows、Collections、Settings 等入口。
- 未实现入口显示为禁用或保留占位，不误导用户进入空白页。

### 需求: 播放 OSD 与弹幕控制
**模块:** ui/player/danmaku
用设计稿 `osd` 的 OSD 结构替换 Media3 默认控制器展示，保留 Media3 播放核心。

#### 场景: 播放控制
用户进入播放页后：
- 视频全屏播放，弹幕覆盖在播放内容上方。
- OK/方向键唤起 OSD，返回键优先隐藏 OSD，再退出播放页。
- 播放/暂停、快退/快进、进度显示和标题元信息在 OSD 中可见。

#### 场景: 弹幕快捷设置
用户在 OSD 中切换弹幕时：
- 弹幕层可暂停/恢复或隐藏/显示。
- 播放暂停时弹幕同步暂停，恢复播放时同步恢复。

## 风险评估
- **风险:** HTML 设计稿未完整定义 Android TV 焦点搜索、输入法、屏幕密度和真实图片加载失败状态。
- **缓解:** 优先使用 TV Compose 焦点模型和稳定尺寸约束；为图片、空列表、错误和加载状态设计占位；执行 1080p/4K 手工截图验收。
- **风险:** 玻璃模糊和图片大图在低端电视设备上可能影响性能。
- **缓解:** 首轮采用半透明层、渐变和有限 blur 效果，不强依赖高成本实时背景模糊；图片加载限制尺寸并使用占位。
- **风险:** 音轨/字幕真实切换依赖 Media3 track selection 和 Emby 媒体流信息，本次若强行实现会扩大范围。
- **缓解:** 本方案仅落 OSD 入口和状态占位，真实切换另行规划。
