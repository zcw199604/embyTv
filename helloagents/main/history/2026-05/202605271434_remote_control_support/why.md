# 变更提案: Android TV 遥控器完整操作支持

## 需求背景
上一轮已落地 Cinematic Glass 配置页、首页媒体中心和播放 OSD，但子代理与本地审查确认当前还不能认定为“完全支持遥控器操作”。这是 Android TV 客户端的核心使用前提，必须保证方向键、OK/Enter、Back、输入框、抽屉和播放 OSD 在纯遥控器场景下形成完整闭环。

已确认的问题：
1. `PlayerScreen` 根容器使用 `onPreviewKeyEvent` 消费方向键和 OK/Enter，可能截断 OSD 内部按钮的焦点移动和点击。
2. `NavigationDrawerPanel` 打开后没有 Back 关闭、初始焦点请求和焦点约束，焦点可能停在背后的首页。
3. 抽屉导航行当前只是展示，不可聚焦、不可点击，也没有禁用项反馈。
4. 首页媒体库卡片可聚焦但 `onClick = {}`，OK 后没有行为，属于伪可用入口。
5. 播放器上一集/下一集、Audio/Subtitles 入口可聚焦但行为为空或只有选中状态。
6. 配置页输入框未定义明确的 TV 输入流程、焦点顺序和 IME action。

## 产品分析

### 目标用户与场景
- **用户群体:** 使用 Android TV、电视盒子或客厅遥控器操作 Emby TV 客户端的用户。
- **使用场景:** 首次输入服务器信息、打开/关闭导航抽屉、浏览首页媒体、进入播放页、唤起/隐藏 OSD、切换弹幕、返回上一级。
- **核心痛点:** TV 端用户通常没有鼠标和触屏，任何“看起来可点但遥控器不可达/无响应”的元素都会阻断主流程。

### 价值主张与成功指标
- **价值主张:** 将当前 UI 从“视觉可用”提升为“遥控器可用”，确保所有可见操作都能通过方向键、OK/Enter 和 Back 完成。
- **成功指标:** 配置页、首页、抽屉和播放页在纯遥控器下无死焦点、无空点击、Back 行为符合预期；核心按键行为具备单元测试或明确手工验收步骤。

### 人文关怀
TV 端应减少用户迷失感：焦点必须始终可见，禁用入口必须给出反馈，Back 必须可预测，输入流程必须允许用户用电视输入法完成配置。

## 变更内容
1. 修复播放器 OSD 的按键分发：不在根容器抢占方向键和 OK/Enter，保留 Back 与唤起 OSD 的全局行为。
2. 为抽屉增加 Back 关闭、打开后初始焦点、焦点限制和导航项可聚焦/禁用反馈。
3. 为首页媒体库卡片、未实现导航入口、上一集/下一集、Audio/Subtitles 等入口提供真实行为或明确禁用提示。
4. 为配置页输入框定义 TV 焦点顺序、IME action 和连接按钮焦点流。
5. 补充遥控器行为 reducer/状态测试和手工设备验收清单。

## 范围边界
- **范围内:** 配置页、首页、抽屉、播放 OSD 的遥控器焦点、OK/Enter、Back、禁用反馈和输入流程修复。
- **范围外:** 新增详情页、真实媒体库分页、真实音轨/字幕切换、真实上一集/下一集播放列表、真实 Emby Connect 配对、全量 UI 自动化框架落地。
- **拆分说明:** 本方案只解决“当前页面所有可见操作必须 remote-ready”。未实现业务能力一律通过禁用态或 Toast/状态提示闭环，不在本方案扩展真实业务功能。

## 影响范围
- **模块:** `ui`、`player`、知识库。
- **文件:** `app/src/main/java/com/embytv/ui/components/CinematicComponents.kt`、`ui/setup/SetupScreen.kt`、`ui/home/HomeScreen.kt`、`ui/home/HomeDashboardModels.kt`、`ui/player/PlayerScreen.kt`、`ui/player/PlayerOsdState.kt`、`app/src/test/java/com/embytv/ui/*`、`helloagents/main/wiki/modules/ui.md`、`helloagents/main/CHANGELOG.md`。
- **API:** 不变更 Emby 远端 API；内部 UI 事件/状态可新增 `RemoteAction`、`DisabledReason`、`DrawerState` 或 OSD action。
- **数据:** 无持久化数据变更；不新增敏感信息处理。

## 核心场景

### 需求: 全局遥控器按键契约
**模块:** ui
统一方向键、OK/Enter、Back 在配置页、首页、抽屉和播放页的职责。

#### 场景: 方向键焦点移动
用户按方向键时：
- 当前可聚焦控件按可预测顺序移动焦点。
- 根容器不抢占子控件的方向键处理。
- 禁用控件不可获得焦点，或获得焦点时必须显示禁用原因。

#### 场景: OK/Enter 激活
用户按 OK/Enter 时：
- 可用控件执行明确动作。
- 未实现能力显示“暂未支持”提示或不可聚焦，不允许空点击。

#### 场景: Back 返回
用户按 Back 时：
- 抽屉打开时先关闭抽屉。
- 播放 OSD 可见时先隐藏 OSD。
- OSD 已隐藏时退出播放页。

### 需求: 配置页遥控器输入
**模块:** ui/setup
配置页必须支持纯遥控器输入服务器地址、用户名和密码。

#### 场景: 输入焦点顺序
用户按方向键或 IME 下一项时：
- 焦点按 Server Address -> Username -> Password -> Connect -> Sample Playback 的顺序移动。
- 当前输入框焦点和编辑状态可见。

#### 场景: 连接提交
用户在密码框或 Connect 按钮上按 OK/Enter：
- 能触发连接或进入电视输入法。
- 加载中禁用重复提交并保持焦点不会丢失。

### 需求: 首页与抽屉遥控器闭环
**模块:** ui/home
首页所有可见入口都必须遥控器可达且有结果。

#### 场景: 抽屉焦点接管
用户打开抽屉时：
- 焦点进入抽屉关闭按钮或 Home 项。
- 方向键不会移动到背后页面。
- Back 或关闭按钮关闭抽屉并把焦点返回菜单按钮。

#### 场景: 首页卡片操作
用户聚焦媒体库或媒体卡片按 OK：
- 媒体卡片进入播放。
- 媒体库卡片若未实现二级页，则显示禁用提示或不可点击。

### 需求: 播放 OSD 遥控器闭环
**模块:** ui/player
播放页必须支持纯遥控器控制播放与弹幕。

#### 场景: OSD 控件焦点
用户唤起 OSD 后：
- 焦点进入播放/暂停或上一次聚焦控件。
- 方向键可在播放控制、进度相关操作、快捷入口之间移动。
- OK/Enter 能触发播放/暂停、快退、快进、弹幕开关等动作。

#### 场景: 未实现播放入口
用户聚焦上一集、下一集、Audio、Subtitles 时：
- 若业务未实现，则控件不可点击或显示清晰“暂未支持”提示。
- 不允许空 lambda 或只改变选中态但无用户反馈。

## 风险评估
- **风险:** Compose TV 焦点搜索在不同设备/系统版本上行为可能存在差异。
- **缓解:** 使用显式 `FocusRequester`、`focusGroup`/焦点约束、`BackHandler` 和最小状态测试；必须补真实设备或模拟器手工验收。
- **风险:** 过度拦截按键会影响 TextField 输入和子控件点击。
- **缓解:** 根容器只处理 Back、OSD 唤起等必要事件；方向键和 OK/Enter 优先交给当前焦点控件。
- **风险:** 未实现业务入口如果保留可点击会误导用户。
- **缓解:** 所有未实现入口统一使用禁用态或状态提示，并在测试/验收中覆盖。
