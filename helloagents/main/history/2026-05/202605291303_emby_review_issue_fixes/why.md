# 变更提案: Emby TV 审查问题修复

## 需求背景
本方案包来自对子代理只读审查结果的整理。当前未提交改动已实现搜索、发现页、收藏、播放队列、音轨字幕等能力，但审查发现仍存在播放上报错绑旧媒体、认证服务器封面可能不显示、搜索旧结果覆盖新结果、TV 遥控器误触危险操作、版本号硬编码不一致等问题。

这些问题会直接影响 Emby 后台播放状态、媒体封面展示、搜索可信度、账号与播放进度安全，以及客户端版本识别，应在本次功能提交前作为修复切片处理。

## 产品分析

### 目标用户与场景
- **用户群体:** 使用 Android TV 遥控器操作 Emby TV 客户端的家庭用户。
- **使用场景:** 浏览媒体库、搜索影片、播放剧集、自动下一集、管理收藏与观看进度、在多账号/多服务器间切换。
- **核心痛点:** TV 端操作不可依赖鼠标键盘，误触成本高；播放状态和封面展示必须与真实 Emby 服务一致。

### 价值主张与成功指标
- **价值主张:** 修复影响真实使用可靠性的审查问题，让客户端在播放、浏览、搜索和账号操作上更符合 TV 端预期。
- **成功指标:** 播放切集上报正确媒体；认证图片能加载；快速搜索不会被旧结果覆盖；危险操作有确认；UI 与 Emby 后台版本一致。

### 人文关怀
TV 端遥控器确认键容易误触，删除凭证和清除播放进度属于用户不易恢复的操作，应提供清晰、可取消、焦点友好的二次确认，避免用户因操作方式限制产生数据损失。

## 变更内容
1. 修复播放器切换上一集/下一集/自动下一集后的 Emby 播放状态上报归属。
2. 补齐认证图片加载策略，避免需要 Token 的 Emby 图片接口无法显示封面。
3. 修复搜索请求取消不完整导致旧查询结果覆盖新查询结果。
4. 为删除保存凭证和清除播放进度增加 TV 遥控器友好的二次确认。
5. 移除版本号硬编码，统一使用应用版本常量或 BuildConfig。

## 范围边界
- **范围内:** 审查提出的 5 个问题修复、对应单元测试/最小 UI 验证、知识库同步。
- **范围外:** 新增转码策略、全局 UI 重设计、Emby API 新功能扩展、播放器内核替换、依赖升级。
- **拆分说明:** 本方案包是当前大功能开发后的质量修复切片，只覆盖审查问题，不扩展新产品能力。

## 影响范围
- **模块:** 播放器、首页/详情页、凭证选择、数据仓库、图片加载组件、版本信息。
- **文件:** `PlayerScreen.kt`、`HomeViewModel.kt`、`HomeScreen.kt`、`CinematicComponents.kt`、`EmbyStreamUrlBuilder.kt`、`EmbyRepository.kt`、相关测试与知识库文件。
- **API:** 不新增 Emby 服务端 API；可能调整图片请求携带认证信息的客户端构造方式。
- **数据:** 不新增本地数据结构；凭证 Token 继续存于加密存储，不写入日志。

## 核心场景

### 需求: 播放切集上报正确
**模块:** 播放器
当用户自动播放下一集，或用遥控器选择上一集/下一集时，当前媒体应先向 Emby 上报 stopped，新媒体后续 progress/pause/stop 只能归属于新媒体。

#### 场景: 自动下一集
当前 Episode 播放到结束，存在下一集。
- 当前 Episode 上报 stopped。
- 下一集开始后 progress/pause/stop 使用下一集 itemId/playSessionId。

#### 场景: 遥控器手动切集
播放中按上一集或下一集按钮。
- 当前 Episode 上报 stopped。
- 切换后不会继续向旧 Episode 发送 progress。

### 需求: 认证封面图片可显示
**模块:** 图片加载与数据仓库
当 Emby 服务器图片接口需要认证时，媒体库、电影、电视剧、剧集、合集、播放列表、类型、演员相关卡片仍应能显示图片。

#### 场景: 认证服务器加载封面
用户已登录，列表中媒体项有图片 ID。
- 图片请求带上有效认证信息。
- Token 不在日志、UI 文本或错误消息中泄漏。

### 需求: 搜索结果与当前关键词一致
**模块:** 首页搜索
用户快速输入多个关键词时，只显示最后一次关键词对应的结果。

#### 场景: 快速连续输入
用户输入 `a` 后立刻输入 `ab`。
- 旧查询被取消或写回前被丢弃。
- 页面展示 `ab` 的加载/结果/错误状态。

### 需求: 危险操作需要确认
**模块:** 凭证选择与媒体详情
删除凭证和清除播放进度前需要二次确认，且遥控器 Back 可以取消。

#### 场景: 删除保存凭证
用户在凭证选择页选择删除。
- 先展示确认弹窗或确认态。
- 只有再次确认才删除。
- Back/取消不删除。

#### 场景: 清除播放进度
用户在媒体详情页选择清除进度。
- 先展示确认弹窗或确认态。
- 只有再次确认才调用 Emby 更新。

### 需求: 版本号一致
**模块:** 应用信息与 Emby 认证头
应用展示版本与 Emby 后台识别版本应和 Gradle `versionName` 保持一致。

#### 场景: 版本显示与后台会话
当前 APK `versionName` 为 `0.2.1`。
- 首页/设置展示 `0.2.1`。
- `X-Emby-Authorization` 中 Version 为 `0.2.1`。

## 风险评估
- **风险:** 图片 URL 携带 Token 可能泄漏到日志或缓存键。
- **缓解:** 优先使用 Coil `ImageRequest` header 注入认证；若临时使用 URL 参数，必须限制日志输出并记录后续替换计划。
- **风险:** 播放器 effect 依赖调整可能引入重复上报 stopped。
- **缓解:** 在 `PlaybackReportingCoordinator` 层保持幂等，并补充切集/退出测试。
- **风险:** 二次确认弹窗焦点不正确会影响遥控器体验。
- **缓解:** 弹窗默认焦点放在取消或安全按钮，Back 明确取消，手工验证 TV 遥控器路径。
